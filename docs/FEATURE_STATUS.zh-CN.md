# 功能状态

[English](FEATURE_STATUS.md) · [返回 README](../README.zh-CN.md)

下面说明哪些功能可以日常使用，哪些需要先开启实验开关。无论使用哪类功能，仍需单独测试自己的恢复方案。

## 核心（Core）

| 能力 | 当前边界 |
|---|---|
| USB 发现与配对 | 首次配对通过 USB 连接，在设备上按提示输入锁屏密码，或解锁后接受 Trust（信任）；无需持续保持解锁或亮屏。 |
| 手动 USB 备份 | 建议先用 USB 完成首次备份。保持设备连接，并核实备份确实完成。 |
| 定时备份 | 使用每设备的时间窗、间隔、电量和充电条件；跳过的任务会等下次调度检查。 |
| 停止备份并暂缓自动计划 | 确认后停止当前任务，自动备份暂缓到主动恢复。暂缓保存成功后跨重启保留，手动备份一次不会解除暂缓。现有备份仍原地更新，中断可能影响上一份备份的可恢复性；不提供暂停续传或回滚。操作说明见[自动备份](manual/scheduling.zh-CN.md)。 |
| [本地备份信息和清单](manual/backup-browser.zh-CN.md) | 手机离线仍可读取本地概况和未加密清单；完整索引跨重启保留，成功备份后后台更新。预览最多 5000 条 / 16 MiB，完整 CSV 需完整清单保存成功。不解密加密清单，也不验证可恢复性。 |
| 手动备份模式 | 默认自动选择，可在高级选项请求全量备份；仍更新当前备份集，不生成历史恢复点。 |
| 持久任务记录 | 有数量、时间与容量上限的摘要和脱敏事件跨重启保留，可在备份管理中复制或导出；记录不包含备份数据。 |
| 只读检查 | 自动检查元数据与完成状态，手动检查未加密清单及文件对象。显示覆盖范围，区分发现问题与无法检查；不修复、不保证恢复成功。 |
| 部署时区 | 经校验的 `TZ` 控制时间窗、页面日期、通知与应用日志；默认 Asia/Shanghai，备份间隔仍为实际经过时长。 |
| 本地 Web UI 与单管理员认证 | 没有遥测或远程前端资源。认证仅面向单管理员，不能让公网暴露变得安全。 |
| 可选通知 | Telegram、SMTP、企业微信、Bark 和 Webhook 只在管理员配置后发送，但不保证每条都能送达；通知失败不会使备份失败。 |
| Wi-Fi 备份 | 必须先通过 USB 成功配对，保留有效 lockdown 记录，网络可达，且设备支持相应的无线通信。长传输可能因休眠或重新连接失败，失败时改用 USB 重试。 |
| 开启/关闭备份加密 | 需要有效主密钥（默认自动保存为 `/configs/secret_key`，或高级配置的原密钥）、在线设备和备份密码；在手机上按提示输入锁屏密码或完成授权即可。必须在应用外另存设备密码和主密钥。 |
| 修改备份密码 | 需要旧密码、新密码和在线设备。丢失备份密码可能导致加密备份无法使用。 |

Core 能力仍需在你的设备和网络上验证。更换设备或升级设备系统后，都应先在非关键设备上完成备份，再启用定时任务；加密备份能否读取、设备能否恢复需要分别验证。

## 实验（Experimental，默认关闭）

| 能力 | 默认门禁 | 风险 |
|---|---|---|
| 整机恢复 | 每设备 `restore_enabled=false` | 会修改设备数据；还需要 CSRF 防护和多重明确确认，目前不能作为已验证的日常恢复方案。 |
| 本地解包 | `IOSBK_ENABLE_EXPERIMENTAL_OPERATIONS=false` | 只支持具有明文 SQLite `Manifest.db` 的完整未加密备份；会生成第二份文件并占用大量磁盘空间。 |
| 删除本地备份 | `IOSBK_ENABLE_EXPERIMENTAL_OPERATIONS=false` | 输入设备名确认后，不可逆地删除该设备的本地备份。 |

全局实验开关只严格接受 `true`。为 false 时，解包/删除控件不会显示，对应 API 会在访问备份状态或文件系统前返回 `403`。开启开关不会绕过 CSRF、输入校验、并发保护和确认步骤。

在重要数据上启用恢复、解包或删除前，必须先做隔离测试，备份当前 `/backups`、`/configs`、`/var/lib/lockdown`，并准备回滚方案。


## 历史恢复点：仅存储基础

已实现内部的凭据代、独立副本准备、可靠发布和重启恢复。历史备份生命周期、保留设置、完整导出与界面尚未开放。计划默认仍为含当天的 3 个自然日，用户可修改，固定点另行保留。普通备份继续原地更新当前备份集。

本地测试覆盖副本隔离、中断和事务恢复。Linux 快速克隆在实际目标路径探测；支持 reflink 的部署文件系统和 NAS 持久性仍需实测。进程退出测试不代表已经验证断电耐久性。
