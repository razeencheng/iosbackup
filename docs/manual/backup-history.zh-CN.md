# 历史恢复点

[English](backup-history.md) · [恢复总览](restore.zh-CN.md)

开发分支已在“备份设置”加入历史设置，在“备份管理”内提供历史子页面。每台设备默认关闭历史功能，原有五项主导航保持不变。

## 开启与保留

在设备的备份设置中开启历史，填写 **1–365 个自然日**，预览后保存。默认 **3 天，含当天**，每日保留最后一个正常点。当天没有成功备份，就不会生成对应日期的点。缩短期限时会展示哪些点将符合后续备份时的自动清理条件；预览过期后需要重新核对。

每次备份使用独立工作副本。通过快速克隆探测的存储可以共享未变化的数据块；其他存储使用完整复制。三份 100 GB 的副本可能占约 300 GB，另需工作空间。页面展示逻辑数据大小；共享块、旧记录未统计大小和文件系统开销会影响实际占用，不能把该数字当作独占磁盘空间。空间不足时停止新备份，保留受保护的历史。

**固定**会让重要时间点免于自动清理。取消固定只恢复其他保留规则，不会立即删除。固定点、最新正常基线、旧加密版本、手动留存和正在读取的数据，都可能使数量超过保留天数。旁边的 `?` 支持鼠标、键盘和触屏说明。

关闭历史后，停止新增和自动清理。已有点转为手动留存，后续普通备份使用独立的可写当前备份集。再次开启时，只对新增结果应用自动规则。

## 查看、检查与删除

进入“备份管理 → 查看历史”，选择日期。执行结果、原始轻量检查和历史保存状态分开显示。**待确认结果**可检查和导出，但不会作为增量基线。导入数据无法确认原始完成时间时，会明确标注。

检查只读：核对元数据，以及可读取清单中的条目和对象是否存在，不逐项验证全部内容哈希，也不证明真机恢复成功。加密清单可能无法本地读取。重新检查只更新证据，不会晋升待确认结果或改写数据。检查证据随历史点保留；任务列表另在自身保留期限内记录检查和点 ID。

删除需要确认所选日期与当前版本。对话框会提示固定和基线状态；正在使用的点不能删除。明确手动删除可以移除最后一份正常基线，使下次需要全量备份，但不会删除其他点或旧密码引用。移除设备不会删除历史：在已移除设备抽屉中选择“查看历史”，无需手机在线，也无需先恢复设备到列表。

## 导出到电脑恢复

1. 选择时间点，点“完整导出”，在五分钟内开始下载。同时最多准备或运行四个会话，实际传输一次一个；等待会话到期后释放读取占用。
2. 下载 `.tar` 文件，其中保留完整原始 `<来源 UDID>/` 目录和加密状态。应用不会把整个文件加载到浏览器内存，也不会在 NAS 上再制作一份同等大小的压缩包。配置、凭据、任务日志和外部索引不在原始来源目录中；保留的解包输出会被排除。
3. “服务端传输已结束”只说明服务端发送结束。请在电脑上确认下载完成；中断或失败后丢弃不完整文件。过期或服务重启后要重新导出，暂不提供断点续传。
4. 解压到新的暂存目录，保留来源 UDID 和全部内容。不要合并同一设备不同日期的目录。然后按 [Finder](restore-finder.zh-CN.md) 或 [Apple Devices](restore-apple-devices.zh-CN.md) 指引放入电脑备份目录并恢复。加密历史需要当时的密码，可能与当前密码不同。

电脑识别、解密和真机恢复仍需单独验收。整机恢复会影响手机上的较新数据；单独提取照片或消息是另一项能力。
